## 0. 结论先行

1. **PCB 的 45° 主要是工艺、电气和密度理由，不是“45° 比 90° 更好看”的视觉研究结论。** 现代数字电路中 90° 拐角的影响通常小到可以忽略；45° 的行业惯性来自酸角、阻抗、微波和布线密度，而不是可读性。[S5][S6][S8][S9][S10]
2. **对络纹而言，纯直角（曼哈顿）是合理的默认；45° 只应以“转角倒角”的形态讨论，不应演变成任意 45° 混合走线。** 这是产品边界，不是纯技术细节。见第 6 节的 A/B/C 选项。
3. **同一输出端口的多条连接，语义上就是“同一张网”（same net）；PCB 上同一张网是一棵铜树，不会复制成两条平行导线。** 因此“单主干 + 分叉”不是视觉偏好，而是与 PCB 语义一致的表达；平行双线反而是错误的视觉隐喻。
4. **当前 `trunkMax = 72px` 的硬上限值得重新评估。** 对远距离源节点，限制主干长度会把分叉点推回源附近，迫使各分支在远离目标处就分开，产生长水平/竖直平行段；把分叉点移到“最近目标投影减去 stub”的合法最晚位置，通常能同时减少重复几何和视觉噪声。这是本报告最有价值的低风险候选，但会改变现有观感，需 A/B。
5. **经验证据的优先级是：交叉 > 拐点/连续性 > 总长度 > 对称。** 不要在对称性上过度设计；真正影响追踪的是交叉、拐点和“这条线是否一直朝目标走”。[S23][S24][S26]
6. **可以立刻落地的纯渲染规则**：同源走廊内禁止平行复制、近共线合并容差、最小腿长、禁止发夹回折、线宽缩放间距、同侧出口按目标顺序分道。**需要组的局部规划**：晚分叉、顺序抽头、T 点间距。**只能离线**：交叉惩罚、全局重路由、push-and-shove 式重排。
7. **45° 倒角（选项 B）是纯渲染实现，但触碰 PRD §5.2 的“曼哈顿路径”边界**，必须由用户明确拍板；选项 C（45° 混合走线）还会改路由算法与验收口径，不建议 v1 采用。

## 2. 真实 PCB 布线的几何规则

### 2.1 方向与角度：45° 与 90° 的真实取舍

PCB 行业长期推荐 45° 走线或圆弧转角，理由主要有四类：

| 理由 | 事实 | 对络纹是否成立 |
| --- | --- | --- |
| 酸角/蚀刻 | 传统蚀刻中，尖锐内角可能形成“酸角”（acid trap），导致过蚀或断线；45° 可避免尖锐内角。现代工艺已大幅缓解，但高可靠设计仍保留该习惯。[S8][S9][S10] | 不成立：没有蚀刻工艺。 |
| 阻抗/反射 | 90° 拐角会增加少量寄生电容，产生微小阻抗不连续；45° 或圆弧可减小。对普通数字信号，单个 90° 拐角的影响通常远小于上升时间对应的电长度。[S5][S6][S7] | 不成立：没有传输线、阻抗和反射。 |
| 微波/高频 | 微波设计中 100 mil 宽线、极快边沿、多级级联时，90° 拐角才需要认真处理；常采用 45° miter 或圆弧。[S5][S33] | 不成立：没有频域。 |
| 布线密度 | 45°/斜向通道可利用对角空间，提高互连密度、减少并行走线，从而降低串扰；该结论在离散布线技术中有明确描述。[S34] | 部分成立：二维画布确实有对角空间，但节点是矩形、端口是轴向，收益不确定。 |

关键事实：

- Howard Johnson 的经典结论：在 8 mil、50 Ω、FR-4 微带、100 ps 上升时间下，一个 90° 拐角的反射约 0.3%，延迟约 1 ps；“直角拐角在数字设计中可以到 2 Gbps 仍然透明”。[S5]
- Altium 的仿真对比：90°、45°、圆弧三种拐角的回波损耗差异很小，TDR 上 90° 仅约 0.5% 的差异。[S6]
- 因此，**“90° 一定有害”是神话；“45° 一定更专业”同样不是普适结论。** 45° 是行业惯例 + 特定工艺/频段的选择。[S5][S6][S8][S9][S10]

对络纹的直接结论：

- **不要因为“PCB 都用 45°”就引入 45° 走线。** 络纹没有酸角、阻抗、反射和层叠；45° 的物理理由在这里不成立。
- 如果引入 45°，唯一站得住的理由是**视觉语言**（更像 PCB、转角更柔和），而不是电学正确性。这必须作为产品决策处理，见第 6 节。

### 2.2 转角处理：miter、chamfer、圆弧

PCB 常见的三种转角处理：

| 形态 | 几何 | 典型用途 | 对络纹的映射 |
| --- | --- | --- | --- |
| 90° 直角 | 一个 90° 顶点 | 普通数字、低成本板 | 当前默认；最正交 |
| 45° 倒角/斜切（chamfer/miter） | 用一个 45° 斜段切掉 90° 顶点；路径变成 90°→45°→0° 两次转向 | 高速、高可靠、习惯性 PCB 风格 | 选项 B；必须限定为“转角倒角”，不是自由斜线 |
| 圆弧转角 | 用一段圆弧连接两条正交段 | 高速、柔性板、追求平滑 | 当前实现已有圆角；PRD §5.2 允许“转角可圆角化” |

尺寸经验（各家口径不完全一致，且都不是 IPC 强制值）：

| 来源 | 建议 | 性质 |
| --- | --- | --- |
| 电子发烧友厂商文 | 45° 倒角距离最好 ≥ 1.5 倍线宽 | 厂商经验 [S30] |
| IPCB 厂商文 | 45° 转角长度最好满足 L ≥ 3W | 厂商经验 [S31] |
| HilPCB 厂商文 | 两折之间的段长应 ≥ 线宽；两角各 45°；线宽保持一致 | 厂商经验 [S32] |
| Altium | Chamfer 以“被切掉的外角占对角线距离的百分比”配置 | 工具实现 [S29] |
| Douville & James | 微波微带的最佳 miter 比例 `M = 52 + 65·exp(-1.35 W/H)` % | 微波公式，不适用于 UI [S33] |

对络纹的建议口径（仅当选择 B 时）：

- 统一用“直角边切角长度 `c`”描述，避免“斜边/直角边”口径混淆。
- `c = clamp(1.5W, 3px, 3W)`；默认线宽 `W=2px` 时，`c = 3–6px`，建议 `4px`（2W）。
- 斜边长度 `c√2`，`c=4px` 时约 `5.7px`；超过 `3W=6px` 的切角会开始被读成“独立斜线”，不再是转角处理。
- 相邻段长度不足 `2c` 时跳过倒角；否则会把短段吃掉。
- 不要同时叠加圆弧和 45° 倒角；二选一。

### 2.3 平行间距与串扰

需要区分两个经常被混为一谈的规则：

1. **IPC-2221B 的导体间距表**：按电压差、内层/外层、是否有阻焊涂层给出的最小电气间隙；例如公开转载的表中，0–15 V 外露导体约 0.10 mm（4 mil），涂覆导体约 0.05 mm（2 mil）。这是**电气安全间隙**，不是串扰规则。[S1][S3]
2. **3W 规则**：平行高速走线的中心间距至少为 3 倍线宽（边到边至少 2W），用于降低容性/感性耦合。它是行业经验法则，不是 IPC 的强制条款；厂商文章常说可减少约 70% 串扰，该数值未独立核实。[S3][S4]

对络纹的映射：

- 没有串扰，但有**知觉拥挤**：两条线太近会被 Gestalt 的接近性原则归为一组，或互相“糊”在一起。[S25]
- 因此“3W”只能借它的**比例思想**，不能照搬数值。建议用线宽 `W` 定义：
  - 最小边到边间隙 `G_min = max(2px, 1W)`；
  - 推荐中心间距 `P = clamp(3W, 5px, 8px)`；
  - `W=2px` 时，`P=6px` 是推荐值；当前 5px 是“2.5W”，可作为密集区域下限。
- 不同来源的线（不同“网”）必须 ≥ `P`；同源分支在共用走廊内应合并成一条主干，而不是并排两条。

### 2.4 分支、总线与 T 点

PCB 的分支拓扑不是只有一种，Altium 的 Routing Topology 规则把常见拓扑定义为：

| 拓扑 | 定义 | 适用 | 络纹映射 |
| --- | --- | --- | --- |
| Shortest | 所有节点按总长度最短连接（默认） | 通用 | 独立基准路径；主干方案的对照基线 |
| Daisy-Simple | 所有节点依次串成链，顺序按最短总长计算 | 高速、减少反射 | 主干顺序抽头（tap）；适合目标沿同一方向分布 |
| Daisy-MidDriven / Balanced | 源在中间，负载分到两侧/多条等长链 | 多负载、时序 | 两侧对称分叉；对称只作次级目标 |
| Starburst | 每个节点直接连到源 | 地网、星形 | 每个目标独立路径；目标包围源时可能更自然 |

来源：Altium Routing Topology 规则。[S14]

其他相关规则：

- **T 点/分支点可加 teardrop**：Altium 支持在 track 与 pad/via 的连接处、以及两条 track 的 T 形连接处加 teardrop，用于增强连接点强度。[S15] 这是物理可靠性措施，不是视觉规则；络纹不应画“连接点圆点”，否则会暗示电气结点。
- **高频避免长 stub**：RF/高速设计中，T 形分支会形成 stub，通常避免；数字总线更常用 daisy-chain 而不是 star。该文也强调“避免长而独立的 stub”。[S35] 对络纹的启示是：**分支应尽量短，且分叉点尽量靠近目标**；不要把主干分叉得太早，然后在远处拉两条长平行线。
- **避免锐角/星形结点**：PCB 上锐角有工艺/电场集中问题；在络纹上没有物理问题，但锐角/星形结点在视觉上会造成方向歧义和“刺点”。正交路由天然把转角限制为 90°，但**发夹回折（180° 反向）**仍会产生视觉锐角，应禁止。

### 2.5 线宽、电流、过孔、层

| PCB 规则 | 内容 | 络纹是否适用 | 可借的部分 |
| --- | --- | --- | --- |
| 线宽/电流 | IPC-2152 用热性能曲线确定载流能力，没有“多少 mil 对应多少 A”的单一表。[S2] | 不适用 | 若未来用线宽表达语义权重，间距必须随线宽缩放 |
| 过孔 | 过孔位置受 via mask、焊盘/走线净空、钻孔候选约束；FreeRouting 会在房间重叠处生成候选，并做 via mask 检查。[S11] | 不适用 | Reroute 可类比“固定过孔”：它是用户给定锚点，路由必须尊重，不可新增/移动 |
| 多层 | 通过换层解决交叉；每层独立规则 | 不适用 | 不能用“换层”消解交叉，所以交叉在络纹里是一等成本，而不是可忽略的副产物 |
| 等长/差分对 | 差分对要求等宽、等距、等长、少拐点；KiCad/Altium 都有差分对与长度调谐工具。[S12][S13] | 不适用 | 同一对节点的多条连接可类比“差分对/线束”：等间距、同弯数、不交叉 |

### 2.6 IPC 标准到底规定了什么

- IPC-2221B 的公开预览目录中可见 **§4 Conductor Spacing**，以及它引用 IPC-2222（刚性板）、IPC-2223（柔性板）等分册。[S1]
- IPC-2152 规定载流能力，不是走线角度。[S2]
- **没有找到“IPC 强制 45° 走线”的可核实条款。** 大量“45° 是 IPC 要求”的说法来自厂商设计指南，不能当作标准强制项。IPC-2221B 正文需购买，具体条款未逐条核对，标 `[未核实]`。
- 因此本报告把“45°/90°”归类为**行业惯例 + 工艺约束**，不是 IPC 几何强制规定。

## 3. EDA 自动布线器的实际启发式

### 3.1 FreeRouting：四阶段 + 房间/门 + shove/rip-up

FreeRouting 官方文档描述了一个很完整的“先粗后细、先快后稳”的流程，和络纹的“主干规划 + 分支 A*”结构高度同构。[S11]

| 机制 | FreeRouting 做法 | 络纹可借的部分 |
| --- | --- | --- |
| 四阶段 | fanout → autoroute passes → optimizer → final clean-up；每阶段可关 | 把“规划 / 清理 / 优化”分层，不在渲染时做全部 |
| 通过上限 | 连续 6 轮无进展或总轮数 30 就停 | 给局部优化设硬预算，失败降级 |
| 连接排序 | 按线宽从宽到窄排，先布电源等“粗网”；每次成功后重读快照并重排 | 主干组按“影响面/目标数”优先规划，而不是按数组顺序 |
| 空间表示 | 把障碍膨胀后切成 x/y 切线的矩形“房间”，用“门”连接；切线上限 1024 条，过密则合并 | 稀疏 Hanan 网格 + 障碍膨胀；络纹已有同类做法 |
| 直接捷径 | 同层两端先试直线或一个 L，免费就立即插入；被挡则试 Z（中腿在 1/8–7/8 处） | “先直连/L，失败再 A*”的分级策略；避免每根线都跑全搜索 |
| 45°/90° 模式 | 中间步骤既非水平也非垂直时转成 L；两个 L 都被挡则转成 Z；45° 模式在 clean-up 阶段切角 | 转角是**后处理**，不是搜索时任意斜线；这与选项 B 的思路一致 |
| Pull tight | 在保持与其他网净空的前提下不断删角，把路径拉直 | 合并共线、删多余拐点、缩短平行走廊；必须带净空检查 |
| 跨网冲突 | 先 shove（最多 20 层，过孔 5 层，绕障 5 层），快照可回滚；shove 不成再 rip-up 整个被穿过的连接，下一轮重布 | 局部、有界、可回滚；绝不全局一次性重排 |
| Rip-up 代价 | 随轮次增长；早期敢推，后期越来越保守 | 滞回/稳定性：节点移动结束后只做有限次清理 |
| 固定对象 | fixed traces 和本网 traces 不被 rip | 不重排无关线路；同组共享主干保持稳定 |

关键启示：

- **“45° 是 clean-up 阶段切角，不是搜索时的自由斜线”**。这与络纹“正交骨架 + 转角处理”的边界完全一致。
- **“先直连/L，失败再搜”** 比“每根线都全搜索”更符合性能预算。
- **“shove 有深度上限、可回滚、只保留更优结果”** 是局部修复的范式；络纹没有节点推挤，但可以做“走廊内换道”的局部 shove，且必须离线。

### 3.2 KiCad：push-and-shove 交互式路由

- KiCad 官方文档描述的交互式路由模式包括：高亮碰撞、推挤（shove）、绕走（walk around）；shove 会把可移动的障碍推开，不能移动的（焊盘、锁定走线/过孔）则绕开。[S12]
- KiCad 官方文档主要描述交互式路由；**未在文档中确认内置 autorouter**，常见做法是配合 FreeRouting 之类的外部工具。此句为工程常识，标 `[未核实]`。
- 对络纹：节点位置不可推（图数据不能改），所以**不能借“推挤节点”**；只能借“推挤走廊内的线路分道”，且这属于渲染几何，不是图数据。

### 3.3 Altium：拓扑规则 + 交互式拐角模式

- Altium 的 Routing Topology 规则明确给出 Shortest / Daisy / Starburst 等拓扑，并说明“高速设计用 daisy chain，地网可用 star，默认 shortest”。[S14]
- 交互式布线支持多种拐角模式（45°/90°/圆弧等），可用快捷键循环；T 形结点可以交互拖动修改。[S13]
- Altium 还支持对 90° 拐角做 chamfer 编辑，参数是“切掉外角的百分比”。[S29]
- 对络纹：**“拓扑是规则，不是单一算法”**。同一组目标在不同分布下，Shortest、Daisy、Starburst 可能各有胜出；应该用一个可解释的拓扑选择器，而不是永远单叉。

### 3.4 TopoR：free-angle 拓扑布线

- TopoR 以 free-angle/拓扑布线著称，官方宣称可减少过孔/层数和走线长度，并支持 45° 形态输出。[S16]
- 对络纹：它是选项 C 的“远亲”——允许任意角度；但络纹的产品身份是正交 PCB 风格，不应跟随。可作为“如果未来要做自由角度实验”的参考，不是 v1 方案。

### 3.5 VLSI 路由理论：与络纹最同构的部分

| 理论/算法 | 内容 | 对络纹的映射 |
| --- | --- | --- |
| Hanan 网格 | 对 rectilinear Steiner 问题，存在一棵最优树，其 Steiner 点都落在经过端点的水平/竖直切线上。[S19] | 络纹的稀疏 Hanan 网格有理论依据；主干分叉点也应优先落在端点的投影线上 |
| RSMT / FLUTE | 多端网的 rectilinear Steiner 最小树；FLUTE 用预计算表可对 ≤9 端极快求最优。[S20] | 主干树本质是“多端网 Steiner 树”的视觉近似；但不要嵌入查表/全搜索到热路径，用 O(n log n) 启发式 |
| Left-edge 通道布线 | 把每根网视为区间，按左端点排序，放进第一条可用轨道，最小化轨道数。[S21] | 走廊分道可用区间着色；但同侧端口分道应保持“顺序保持”，不要为了少轨道而换序 |
| PathFinder 协商拥塞 | 允许临时共享/冲突，用历史代价逐轮 negotiation，最终消除拥塞。[S22] | 只适合离线清理；不能每帧跑；可作为“走廊占用历史惩罚”的理论依据 |

**结论**：络纹的“主干规划”对应 VLSI 的 global routing，“分支 A*”对应 detailed routing；这是正确的分层。不要把它们合成一个每帧运行的大搜索。

## 4. 视觉与认知：为什么“单主干 + 统一拐点”更整齐

### 4.1 Gestalt 原则

Wagemans 等人的百年综述把经典分组原则列为：接近、相似、共同命运、良好连续、闭合、对称、平行等；新原则包括共同区域、元素/均匀连通性等。[S25]

| 原则 | 对连线的含义 | 对络纹的用法 |
| --- | --- | --- |
| 良好连续（good continuation） | 人倾向于把平滑、连续、方向一致的轮廓看成一个对象 | 同一端口的多条连接应共线到分叉点；分叉前必须是一条线 |
| 接近（proximity） | 靠得近的元素被归为一组 | 不同来源的线必须拉开 ≥P；同源分支在走廊内应合并，而不是并排 |
| 相似（similarity） | 外形/颜色相似的元素被视为同类 | 同一端口的线同色、同宽；不要用并行双线制造“两个信号”的错觉 |
| 共同命运（common fate） | 一起变化/运动的元素被归组 | 拖动时同源分支应保持共线关系，不要各自漂移 |
| 共同区域（common region） | 同一区域内元素被归组 | 不建议用背景色块圈住主干；会增加视觉噪声，连续线本身已足够 |

### 4.2 经验研究给出的优先级

- **Purchase 1997**：在线实验表明，**交叉（crossings）是最重要的美学因素**；拐点（bends）和对称性影响较小；最大化最小角、最大化正交性没有显著影响。[S24]
- **Ware 等 2002**：在最短路径任务中，路径长度之后，**连续性（continuity）和交叉**是最重要的因素；中间节点的额外分支数量也有影响。论文明确指出“多边路径尽量保持笔直”的重要性被低估。[S23]
- **Huang 2009**：人有“测地线路径倾向”（geodesic-path tendency）——搜索路径时会优先跟随指向目标的线。[S26]
- **交叉角**：Ware 的研究表明锐角交叉更难读；正交路由的所有交叉天然是 90°，这是正交风格的一个真实优势。[S23]

由此得到可执行的优先级：

1. **硬约束**：不穿节点、不穿自身卡片、端口方向自然、无零长度/发夹。
2. **交叉**：能避免就避免；不能避免时保持 90° 交叉。
3. **拐点/连续性**：每个多余拐点都是认知成本；同源路径在分叉前必须连续。
4. **总长度/唯一几何长度**：共享主干减少重复几何，但不能让单个目标绕行超预算。
5. **间距/拥挤**：不同网 ≥P；同源合并。
6. **对称/平衡**：只做 tie-breaker，不为对称牺牲拐点或长度。

**注意一个反直觉点**：Purchase 的研究中“最大化正交性”没有显著影响；Ware 也指出曼哈顿布局未必比平滑曲线更易读。**所以“正交 = 更整洁”不能当作已证结论。** 正交的真正收益是：交叉角固定为 90°、方向轴少、与 PCB 语义一致、便于网格对齐；代价是每个拐点都打断连续性。因此设计目标应是“**正交 + 少拐点 + 高连续**”，而不是“只要是直角就好看”。[S23][S24]

### 4.3 为什么“同一端口单主干”是对的

- PCB 的“网（net）”是一组必须连通的引脚；同一张网在铜层上是一棵**树**，不是两条并行复制品。Altium 把 net topology 描述为“pin-to-pin connections 的安排方式”。[S14]
- 络纹的同一输出端口 = 同一个信号源；多条连接 = 同源 fan-out，语义上就是一棵树。把它画成两条平行线，等于把“一个信号”画成“两个信号”，既不符合语义，也违反良好连续。
- 因此，**DEC-009/DEC-010 的“单主干 + 分叉 + 公共前缀”方向与 PCB 语义一致**，不是临时补丁。后续应把这条规则写成“同源即同网”的判定，而不是靠像素阈值碰运气。

## 5. 45° / 倒角专题（本次补充重点）

### 5.1 PCB 为什么大量使用 45° 与倒角

把理由拆开看，不要混成一句“45° 更好”：

| 维度 | 45°/倒角的作用 | 证据 | 对络纹的适用性 |
| --- | --- | --- | --- |
| 工艺 | 避免尖锐内角形成酸角；高可靠板仍常保留 | 厂商文章一致 [S8][S9][S10] | 不适用（无蚀刻） |
| 电气 | 减小 90° 拐角的寄生电容/阻抗突变；微波/10 Gbps+ 才有明显意义 | Johnson、Altium 仿真 [S5][S6][S7] | 不适用（无传输线） |
| 密度 | 对角通道可利用斜向空间，提高互连密度、减少并行走线 | 离散布线论文 [S34] | 部分适用，但节点是矩形，收益不确定 |
| 工具惯例 | 多数 EDA 默认 45°；设计规范沿用 | 行业指南 [S8][S9] | 不适用（工具惯例不是理由） |
| 视觉 | “看起来更像 PCB”“转角更柔和” | 设计推断 [C] | 唯一可能的理由，但未经本项目实测 |

**重要区分**：

- **45° 倒角（转角处理）**：在 90° 顶点切一小段 45°，路径仍以水平/竖直为主；只改变转角局部。
- **45° 混合走线**：允许路径中段任意 45° 段，方向集合从 2 个变成 4 个；这是路由算法层面的改变。

两者不能混为一谈。络纹如果要碰 45°，只应讨论前者。

### 5.2 45° 倒角的尺寸：没有统一标准

- 厂商经验给出 ≥1.5W、≥3W、两折间段长 ≥W 等不同口径；这些是经验法则，不是 IPC 强制值。[S30][S31][S32]
- Altium 的实现是按“切掉外角的百分比”配置，而不是固定像素。[S29]
- 微波 miter 有 Douville–James 公式，但它依赖线宽/介质厚度，属于微波设计，不应直接搬到 UI。[S33]

**络纹建议**（若采用 B）：

- 用直角边切角 `c` 定义；`c = clamp(1.5W, 3px, 3W)`。
- `W=2px`：`c` 建议 `4px`（2W），范围 `3–6px`；斜边约 `4.2–8.5px`。
- 相邻段长度 `< 2c` 时跳过倒角；不要吃掉短段。
- 转角后的第一段/最后一段仍需满足最小腿长；T 点不倒角。
- 不要叠加圆弧与倒角；二选一，否则形成双重转角。

### 5.3 45° 的视觉收益与代价

| 可能收益 | 代价/风险 |
| --- | --- |
| 更像真实 PCB，转角有“斜切”的工艺感 | 引入第三个方向，破坏“横平竖直”的纯正交语言 |
| 转角看起来不那么“硬” | 每个倒角增加 2 次方向变化；Purchase/Ware 的证据表明拐点有认知成本 [S23][S24] |
| 长转角处可能更顺眼 | 2px 线宽下 4px 倒角很微妙；`c>6px` 会被读成独立斜线，不是转角 |
| 与 PCB 规范习惯一致 | 络纹没有工艺/电气理由；纯视觉收益未经实测 |

**判断**：45° 倒角不是“更整齐”的必然答案，它是一种**风格选择**。如果目标是“柔和”，现有圆弧更合适；如果目标是“PCB 工艺感”，倒角更合适。两者不应同时存在。

### 5.4 决策选项 A / B / C

> 结论标注：**A 为纯渲染且完全合规；B 的实现是纯渲染，但触碰 PRD §5.2“曼哈顿路径”边界；C 既触碰 PRD，又改路由算法。B/C 必须由用户拍板。**

#### 选项 A：保持曼哈顿 + 现有圆角（默认）

- 几何：水平/竖直段 + 90° 转角；转角用现有圆弧（`radius=10px`，受相邻段长度限制）。[S29 类似工具行为；络纹 `trace.js` 当前实现]
- PRD：合规；§5.2 明确“使用曼哈顿路径”“转角可圆角化”。[PRD §5.2]
- 实现影响：无新增；保留现有 `emitSmoothPath`/圆角。
- 避障/主干：不变；共享几何逻辑不变。
- 视觉：最正交、最稳定；圆角提供柔和感；没有 PCB 斜切感。
- 子变体 A0：把 `radius` 设为 0，得到纯直角（无圆角）；仍是纯渲染，PRD 合规，但视觉更硬。
- 建议：**默认 A**；若用户明确要“纯直角”，用 A0。

#### 选项 B：转角 45° 倒角（chamfer）

- 几何：只在**凸转角**把 90° 顶点替换为一段 45° 斜切；其余段保持水平/竖直；T 点不倒角。
- PRD：**边界**。§5.2 要求曼哈顿路径；45° 斜段不是曼哈顿。需要一条明确例外：“转角倒角允许 ≤3W 的 45° 斜切，不属于走线方向”。这必须用户拍板，并回写 PRD/决策记录（由主线做，不在本报告改）。
- 实现影响（纯渲染，不改图数据）：
  1. 在最终路径发射阶段做 `chamferPolyline(points, c)`，不改路由搜索结果。
  2. 必须在 `sharedPrefix` 合并后的树上做；若逐 link 做，同一主干角会因相邻段长度不同得到不同 `c`，重新产生 1–3px 错位。
  3. 只用凸角；凹角切角可能把路径推进障碍物安全区，直接跳过。
  4. 转角三角区做一次净空采样；侵占节点安全区则退回 90°。
  5. T 点/分支起点不倒角；分支第一段需 ≥`minLeg`，否则 T 会变成 Y。
  6. 命中测试保留正交折线；渲染路径倒角；`hitSlop` 至少 `c√2/2 + 2px`。
  7. 与圆弧互斥；不要在圆弧上再切角。
- 避障影响：转角三角区落在原转角方格内；凸角是“切掉材料”，通常安全；但仍要采样检查。主干/分支的障碍路径本身不变。
- 主干共用影响：正向——倒角在合并后统一处理，共享角完全一致；反向——若处理顺序错误，会重新制造平行错位。
- 视觉收益：更像 PCB、转角更 crisp；但会增加 2 次方向变化和一条短斜线；`c=4px` 时收益细微，`c>6px` 时开始像“斜线走线”。
- 建议：**默认关闭**；如果用户明确要 PCB 斜切风格，做 A/B 截图对比后再启用。

#### 选项 C：允许 45° 混合走线

- 几何：路径中段允许 45° 段；方向集合从 2 个变为 4 个（octilinear）。
- PRD：**明确违反** §5.2 的“曼哈顿路径”；需要重写 PRD、验收口径和视觉规范。必须用户拍板。
- 实现影响（不只是渲染）：
  1. 路由搜索结果从 4 邻域变成 8 邻域；A* 扩展约 2 倍，搜索预算需重估。
  2. 障碍膨胀/净空检查要处理斜段扫掠区域；不能只按矩形格点判断。
  3. 主干共用检测要支持斜向共线/平行；`sharedPrefix` 的轴向假设失效。
  4. 分道/线束要在斜向坐标上做间距；T 点可能变成 Y 形，出现 45° 分支。
  5. 命中测试、圆角、简化、单元测试的“所有段水平/竖直”断言全部要改。
  6. 交叉角不再固定 90°，可能出现锐角交叉（Ware 证据：锐角交叉更难读）。[S23]
- 视觉收益：某些长斜向连接可以更短（纯几何上，45° 对角线与曼哈顿路径相比，理论最大节省约 29%，实际受端口方向和障碍限制）；可能更像 metro map 的 octilinear 风格。但节点图密集、短边、2px 线宽，收益未被证实；方向变多可能更乱。
- 建议：**v1 不采用**；如果未来要做，作为独立实验模式（例如“PCB free-angle”开关），不要改默认正交身份。

#### A/B/C 对照表

| 维度 | A（曼哈顿+圆角） | B（转角 45° 倒角） | C（45° 混合走线） |
| --- | --- | --- | --- |
| PRD §5.2 | 合规 | 边界，需书面例外 | 违反，需改 PRD |
| 图数据 | 不改 | 不改 | 不改（仍可只改渲染，但路由算法变） |
| 路由搜索 | 不变 | 不变（后处理） | 4→8 邻域，预算上升 |
| 避障 | 不变 | 转角三角区需检查 | 斜段扫掠检查，复杂 |
| 主干共用 | 不变 | 必须在合并后统一倒角 | 斜向共线/平行检测，复杂 |
| T 点 | 90° T | 不倒下角，仍 90° T | 可能变 45° Y |
| 视觉 | 最正交、稳定 | 更像 PCB、较 crisp | 方向更多、可能更短也可能更乱 |
| 结论 | **默认** | **可选，需拍板** | **不建议 v1** |

### 5.5 哪些是纯渲染，哪些是 PRD 边界

| 改动 | 是否纯渲染 | 是否改图数据 | 是否触碰 PRD | 说明 |
| --- | --- | --- | --- | --- |
| A 现状 / A0 纯直角 | 是 | 否 | 否 | 只改绘制 |
| B 转角 45° 倒角 | 是（实现层面） | 否 | **是** | 需要 §5.2 例外条款；不是自由斜线 |
| C 45° 混合走线 | 否（改路由） | 否 | **是** | 需要重写 PRD 与算法 |
| 晚分叉 / 顺序抽头 | 是（组局部规划） | 否 | 否 | 只改几何，不改链路语义 |
| 走廊分道/换道 | 是 | 否 | 否 | 但必须在几何版本变化/离线做 |
| 拖动磁吸对齐 | 否（改节点位置） | **是** | **是** | 尚未定案；本报告不建议纳入 v1 |

## 7. 映射到络纹的具体做法

### 7.1 语义判定：同源 = 同网

| 络纹场景 | PCB 类比 | 正确表达 | 错误表达 |
| --- | --- | --- | --- |
| 一个输出端口连多个目标 | 同一 net 的 fan-out | 一棵树：主干 + T 点分叉 | 从端口就并排多条线 |
| 不同端口进同一目标槽 | 不同 net 汇聚到同一 pad | 各自独立，按顺序分道，最小间距 P | 画成一条线/重叠 |
| 同一对节点多条连接 | 同一对端点之间的多条 net/线束 | 平行线束：等距、同弯数、不交叉 | 交织/辫子 |
| 反向连接（目标在源左侧） | 反向走线 | 允许反向，但避免长距离回折；绕行预算内 | 为了“向右流”强行绕大圈 |

**结论**：R01 是语义规则，不是像素规则。实现上可用“同一 origin port id + 同组”判定，不要靠 5px 距离猜。

### 7.2 T 点怎么定：从固定 72px 改为“合法最晚 + 顺序抽头”

当前实现的约束（供对照）：

- `trunkPlan.js:17-18`：`TRUNK_MIN=16`，`TRUNK_MAX=72`。
- 分叉长度取“最近目标投影 - stub”，再被 `TRUNK_MAX` 截断。
- 分支从 T 点各自跑 A*；`sharedPrefixLength` 合并公共前缀。

问题：

- 对远距离源（例如源在目标左侧 800–1000px），`TRUNK_MAX=72` 会把 T 点拉回源附近；分支在远离目标的位置就分开，形成两条长水平段/长竖直段。DEC-010 的公共前缀能把它们合并，但只是“事后补救”，不是最优拓扑。
- 从“唯一几何长度”看，主干每延长 1px，重复几何减少 `(n-1)` px（在所有目标都在 T 之后且不折返的前提下）；72px 的上限让这个收益被人为截断。
- 从认知看，测地线倾向希望线一直朝目标走；T 点太早会让分支先横向再折回，违背“朝目标”的直觉。[S26]

建议的 T 点算法（组局部，O(n log n)，不跑 A* 时可退化为几何构造）：

```text
输入：源端口 pin P，方向 d，目标端口 T_i，stub S，最小腿 Lmin，T 点间距 Gtee
p_i = dot(T_i - P, d)          # 沿主干方向的投影
q_i = cross(T_i - P, d)        # 侧向偏移
eligible = { i | p_i > S + Lmin 且 第一段方向与 d 一致 }
若 |eligible| < 2：全部独立

按 p_i 升序排序
按 gap <= Gtee 聚簇（Gtee 建议 24px）
对每个簇 c：
    p_min = min(p_i in c)
    T_c = clamp(p_min - S, TRUNK_MIN, min(p_min - S, corridorLimit(d)))
    若 T_c < TRUNK_MIN：该簇独立
    在 T_c 建一个分叉；簇内目标共享这段主干
相邻簇的 T_c 间距 < Gtee 时合并
接受条件：
    每个目标 detour <= 现有预算（1.25 / 1.35 / 1.15）
    uniqueLength(tree) 比独立基准减少 >= 5–10%
    分支顺序保持（不产生交叉）
否则：回退独立/当前候选
```

关键点：

- **`T_c = p_min - S`** 是“合法最晚分叉”：再晚就会让最近目标折返；再早就会产生不必要的平行段。
- **去掉固定 `TRUNK_MAX=72`**，改用 `corridorLimit`（前方障碍）和 `p_min - S`（最近目标）共同约束。长主干本身不是问题；一条长主干比两条长平行分支更符合“同网一棵树”。
- **目标分散时用顺序抽头**：每个目标在自己的投影处 `T_i = p_i - S` 抽头；目标聚簇（投影差 ≤ `Gtee`）时用一个分叉。这样 3+ 目标不会都从同一个远处 T 点拉出多条长分支。
- **T 点必须在自由空间**：距节点主体 ≥ `C_node`；不能在另一个 T 点附近（`< Gtee`）再开叉；不能在端口上。
- **分支首段 ≥ `Lmin`**：否则 T 点看起来像“毛刺”或 Y 形；不足则合并到上一个分叉/独立。
- **顺序保持**：同侧分支按目标侧向坐标排序；若顺序会交叉，优先回退独立或换另一侧，不强行产生交叉。

**这是一个行为变化，不是纯参数**：它会影响所有远距离多头连接的观感，需 A/B 截图对比（近、远、上下、反向）后再决定。单元测试里若有“T ≤ 72”的断言，需要同步更新。

### 7.3 多目标拓扑选择：Shortest / Trunk / Daisy-Taps

用 PCB 拓扑规则做一个可解释的选择器，而不是永远单叉：

```text
候选 A：Shortest（每个目标独立）
候选 B：Trunk（单叉 + 共享主干）
候选 C：Daisy-Taps（主干 + 按投影顺序抽头）

对每个候选计算：
  L_unique = 主干 + 各分支的唯一几何长度
  Bends = 总拐点数
  Cross = 组内交叉数（可用的缓存段集合）
  DetourMax = max(实际路径 / 独立路径)
  SpacingViolation = 违反 P 的数量
选择：
  先淘汰 DetourMax 超预算、SpacingViolation > 0、穿节点体的候选
  再按 Cross > Bends > L_unique > 对称 的字典序选择
  若收益 < 5–10%，保留上一版候选（滞回）
```

- **目标聚簇**（投影接近、侧向分散）：Trunk 单叉通常最好。
- **目标沿主干分散**：Daisy-Taps 通常最好；每段分支短，主干连续。
- **目标包围源/无共同走廊**：Shortest 或 Starburst；不要硬造主干。
- **目标在源左侧（反向）**：单独处理；不要为了主干强行绕到右侧再回来。

来源：Altium 的 Shortest / Daisy / Starburst 拓扑规则。[S14]

### 7.4 间距、线束与分道

| 场景 | 规则 | 建议值 |
| --- | --- | --- |
| 不同源线同走廊 | 中心间距 ≥P；不得共线重叠 | `P = clamp(3W, 5, 8)`；W=2 → 6 |
| 同源分支共用走廊 | 合并为一条主干，直到真正分歧 | 共享前缀 ≥16px；合并容差 1px |
| 同 pair 多连接 | 等距线束，同弯数，不交叉 | 现有 5px 分道；建议按 P 复算 |
| 同侧端口 fan-in | 按目标顺序分道，顺序保持 | 现有 y 排序保留；不要为省轨道换序 |
| 同侧端口 fan-out | 按目标顺序分配出口，避免交叉 | 输出侧统一 stub 24px（DEC-011） |
| 密集区域 | 允许降到 `P_min = max(2W, 4px)`，但不得重叠 | 仅软降级；记录诊断 |

关于 left-edge/区间着色：

- 它能最小化轨道数，但会**重排**区间；在同侧端口 fan-in 场景，重排会造成端口处的交叉。因此**不要直接替换现有“按 y 排序”**。[S21]
- 它更适合“不同源、同一走廊”的离线分道：按起点排序、放到最低可用轨道；冲突时局部绕行或换道。作为 P2 可选。

### 7.5 转角、最小腿、近共线

| 规则 | 当前 | 建议 | 说明 |
| --- | --- | --- | --- |
| 圆角半径 | `10px`，受相邻段 1/3 限制（`trace.js`） | 保留 `R=10`；下限 `3W=6` | 圆角是 PRD 允许的 |
| 最小腿长 | 未显式约束 | `Lmin = max(4px, 2W)` = 4px | 短于此的段读成噪声；也会让 T 点发毛 |
| 近共线合并 | 文档允许 ≤3px 短竖段 | `flatTol = min(3, 1.5W)` = 3px | 与现有口径一致 |
| 发夹回折 | 端口重叠时允许 | 有空间时禁止；无空间时保留 | 0°/180° 反向是视觉锐角 |
| 共享前缀合并容差 | 0.5px（`trunkPlan.js`） | 1px（同源）；不同源不合并 | 避免浮点误差重新分裂 |
| 重复共线段 | simplify 去共线 | 增加“同源同几何”自检 | 防止 1–3px 平行双线回归 |

### 7.6 优先级与代价模型

建议把代价分成“硬约束 + 软代价”，不要把所有东西塞进一个 A*：

```text
硬约束（不可接受）：
  穿节点主体 / 穿自身卡片
  端口首段方向不合法
  零长度段、发夹回折（有空间时）
  不同源线共线/重叠
  最近目标折返超出预算

软代价（字典序优先）：
  1) 交叉数 X
  2) 拐点数 B
  3) 唯一几何长度 L_unique
  4) 间距违反/拥挤 S
  5) 对称偏差 Sym

A* 内部仍用：
  g = length + BEND_COST * bends + BLOCKED_MULT * blocked
  其中 BEND_COST = 24px（当前），建议 B = max(24, 12W)
```

- 交叉惩罚若要做，建议 `wX = 2 × BEND_COST = 48px/交叉`，但只在组内/缓存段上算；不要每帧全图扫描。
- 若没有交叉计数，保持当前“长度 + 拐点”即可；不要为了“可能更好”引入昂贵的全局搜索。
- 现有 `BEND_COST=24px` 在合理区间；它是“宁可多走 24px 也不多一个拐点”的等价长度。可按 `B=24–32` 做 A/B，但不要凭感觉改。

### 7.7 计算分层（必须守住 PRD §10.1）

| 层 | 允许做什么 | 禁止做什么 |
| --- | --- | --- |
| 渲染每帧 | 读取已算好的路径；圆角/倒角后处理；描边 | A*、候选树搜索、全图重规划、遍历所有 link 求交叉 |
| 节点移动结束/几何版本变化 | 同源组重算；T 点/抽头；共享前缀；局部 lane 分配 | 全图所有组一起重排；多轮 rip-up |
| 拖拽结束后的空闲 | 有限次 pull-tight；组内换道；交叉统计 | 无限迭代；改节点位置 |
| 离线/实验 | 全局交叉优化、PathFinder 式 negotiation | 进入默认热路径 |

来源：PRD §10.1“渲染热路径只读取已经计算好的路由，不执行完整 A* 或共享树搜索”。[PRD §10.1]

| `chamferHitPath`（B） | 无 | 保留正交折线 | `hitSlop ≥ c√2/2+2` | 命中稳定 [C] | 交互 | 热路径 |
| `octilinear`（C） | 无 | false | 8 邻域 A* | PRD 边界 | 路由 | 组局部 |
| `magneticSnap` | 无 | 关闭 | 需改节点位置 | PRD 边界 | 图数据 | 不适用 |

## 10. 分期与验证指标

### P0：纯渲染、低风险（不改 PRD）

- 同源走廊内禁止平行复制；共享前缀容差 1px。
- 最小腿长 4px；有空间时禁止发夹回折。
- 近共线 3px 合并；圆角半径受相邻段限制。
- 不同源线中心间距 ≥5px（推荐 6px）。
- 同侧端口 fan-in 保持按 y 排序；输出侧统一 stub 24px。
- 验收：同一端口多连接在端口附近始终单条；共用走廊段完全重合；不同源线不重叠。

### P1：组局部拓扑（不改 PRD，但会改观感）

- 晚分叉：`T = min(p_min - S, corridorLimit)`，去掉固定 72px。
- 顺序抽头：目标投影分散时按 `T_i = p_i - S`；聚簇时单叉。
- T 点最小间距 `Gtee=24px`；分支首段 `Lmin=4px`。
- 同 pair 线束等距、同弯数、不交叉。
- 验收：远距离多头不再出现“源附近分叉 + 目标附近长平行段”；T 点数量不异常增加；绕行预算不回归。

### P2：离线清理/可选交叉优化

- Pull-tight：净空前提下删多余拐点/共线。
- 组内换道：同源/不同源走廊的有限次换道；不做全局。
- 交叉统计与可选 `wX`；只在几何版本变化/空闲跑。
- 验收：拐点中位数下降；交叉数不增加；热路径耗时无明显上升。

### P3：产品边界（必须拍板）

- B：45° 转角倒角；先 A/B 截图，再决定是否写入 PRD 例外。
- C：45° 混合走线；v1 不做；如做，独立实验开关。
- 磁吸对齐：会改节点位置，另行立项，不纳入本报告。

### 建议的验证指标

| 指标 | 目标 | 说明 |
| --- | --- | --- |
| `same_origin_parallel_pairs` | 0 | 同源、非完全共线、间距 <1.5W 的配对数 |
| `different_origin_min_gap` | ≥P | 不同源线的最小中心距 |
| `hairpin_count` | 0（有空间时） | 0°/180° 反向段 |
| `median_bends_per_link` | ≤4；p95 ≤6 | 诊断拐点成本 |
| `crossing_count` | 不增加 | 与上一版对比 |
| `trunk_fork_ratio` | `T/(p_min-S)` ≥0.8（晚分叉目标） | 诊断 72px 上限是否仍在截断 |
| `hot_path_ms` | 不高于基线（允许 ±5%） | 渲染帧耗时 |
| `data_diff` | 0 | Link ID/slot/节点数据零变化 |
| `chamfer_at_T`（B） | 0 | T 点不得倒角 |
| `chamfer_c`（B） | 3–6px | 不得读成自由斜线 |

## 11. 待用户拍板的取舍

1. **A / B / C 选哪个？**
   - 建议默认 A（现状圆角）；若你要“纯直角”，用 A0（`radius=0`）。
   - B 只在“明确要 PCB 斜切风格”时启用，且需要 PRD §5.2 的书面例外；建议 `c=4px`。
   - C 不建议 v1；它会改路由算法并破坏正交身份。
2. **是否允许把 `TRUNK_MAX=72px` 改为“合法最晚分叉”？**
   - 这是本报告收益最大的候选，但会改变远距离多头连接的观感；建议先做 A/B 截图再定。
3. **是否引入顺序抽头（Daisy-Taps）替代“单叉 + 公共前缀”？**
   - 对 3+ 分散目标更干净，但实现比“去掉 72px”大；可作为 P2。
4. **是否要做交叉惩罚/离线清理？**
   - 经验证据支持“交叉最重要”，但全局扫描有性能代价；建议只在组内/离线做。
5. **磁吸对齐是否单独立项？**
   - 它会改节点位置，属于图数据边界；本报告不建议混入连线渲染。

## 13. 附录：三条可直接评审的伪代码

### A. 晚分叉 + 顺序抽头

```text
plan(group, P, d, S, Lmin, Gtee):
  for each target t:
      p[t] = dot(t.pin - P, d)
      q[t] = cross(t.pin - P, d)
  keep = { t | p[t] > S + Lmin and firstRunDir(t) == d }
  if |keep| < 2: return independent(group)

  sort keep by p
  clusters = clusterByGap(keep.p, Gtee)
  for c in clusters:
      pMin = min(c.p)
      T = pMin - S
      T = min(T, corridorLimit(P, d))     # 前方障碍
      if T < TRUNK_MIN: return independent(c)
      forkAt(T)
      for t in c: branchFrom(T, t)
  mergeClustersIf(forkGap < Gtee)
  if detourExceeded or crossing or spacingViolation:
      return fallback(group)
  return tree
```

### B. 转角倒角（仅在选 B 时）

```text
chamfer(polyline, W):
  c = clamp(1.5 * W, 3, 3 * W)
  out = []
  for each vertex v with prev/next:
      if v is T-junction: keep(v); continue
      if adjacent leg < 2 * c: keep(v); continue
      if cornerTriangleNotClear(v, c): keep(v); continue
      p1 = v - unit(prev->v) * c
      p2 = v + unit(v->next) * c
      out += [p1, p2]        # 中间自动形成 45° 斜段
  return out
# 必须在 sharedPrefix 合并后的树上调用
# 命中测试仍用原正交折线
```

### C. 同侧端口分道（保持顺序）

assignLanes(links, side):
  if side == sameTargetSlot:
      sort links by target.y
      # ups: 从 pin 向上递增；downs: 从 pin 向下递增

  else:

## 14. 一句话总结

PCB 值得络纹借的不是“45° 这个角度”，而是四件事：**同一张网画成一棵树、分支尽量晚而短、平行线必须有明确间距、转角处理只能是局部装饰而不是走线方向**。把这四件事写成参数和优先级，比争论“45° 还是 90°”更能改善观感。
