## 0. 决策摘要

络纹是一款面向 ComfyUI 的智能连线与线路整理扩展。它通过更清晰的线路样式、空间感知的路径规划、节点避障、线路分道，以及多目标连接的自适应主干/分叉，降低复杂工作流中的“线团”现象，帮助用户更快理解数据流向。

**产品核心原则：改善线路表达，不改变工作流本身。**

### 已锁定的关键决策

1. **两种线路样式都支持：** 平滑曲线（Bezier / Spline）与正交折线（Orthogonal / PCB）。线路样式与路由决策分层，不能把样式选择和是否共享主干混为同一设置。
2. **单条连接独立寻路是基准：** 先计算每条连接的独立路径，再评估是否值得共享主干。
3. **多目标采用自适应树形路由：** 同一输出端口连接多个目标时，允许全部合并、部分合并或完全独立；由空间和综合成本决定，不强制共享。
4. **单目标绕行受保护：** 不能为了缩短总线路长度，让某一个目标明显绕远。
5. **只改绘制，不改图数据：** 自动主干、分叉点、路径坐标均为运行时派生数据；不自动创建 Reroute，不更改原生 Link，不改变执行语义。
6. **手工意图优先：** 用户明确放置的 Reroute、手工线路整理和已存在的手动线束，不得被自动算法覆盖。
7. **稳定性优先于炫技：** 路由缓存、局部重算、滞回、确定性结果和原生渲染降级必须从第一版纳入设计。
8. **成熟项目以研究和合规复用为主：** 参考 Cable Management、NKD Reroutes、Zip Ties；不得忽略各项目许可证和交互边界。

## 1. 背景与问题定义

ComfyUI 的节点工作流在连接数量增加后，常出现以下问题：

- 多条线路交叉、覆盖或重叠，难以辨认来源和目标。
- 节点移动后，原本合理的线路变成绕行、折返或穿越节点。
- 一个输出连接多个目标时，重复线路容易形成视觉噪声。
- 传统“所有线都独立绘制”不能表达自然的公共路径；强制合并又会导致个别目标绕路。
- 过度依赖用户手动放置 Reroute，会增加工作流整理成本，并可能让流程结构越来越复杂。
- 只优化静态截图而忽略悬停、选择、拖动、断开、撤销等交互，会使扩展虽好看却不好用。

络纹要解决的核心问题不是“把线画直”，而是：

1. 让用户快速看懂节点间的数据连接关系。
2. 在节点布局不变的前提下，减少不必要的线路绕行、交叉和视觉拥挤。
3. 当一个输出连接多个目标时，识别空间上适合共享的区段，形成自然的主干与分叉。
4. 当共享主干不划算时，保留独立路线；不要让算法为了合并而合并。
5. 让用户已有的手动整理方式继续有效。

**第一性原理：线路应服从节点布局，而不是让节点布局服从线路。**

## 2. 产品定位、目标与非目标

### 2.1 产品定位

络纹是 ComfyUI 的前端连线呈现与自动路由扩展，不是新工作流引擎，也不是节点编辑器重写项目。

产品价值：

- 让连线更清晰、更易读。
- 自动绕开节点主体，减少线路互相遮挡。
- 根据空间情况整理多个目标之间的连接关系。
- 尽量不增加用户手工操作，不改变原工作流的数据结构。

### 2.2 产品目标

- 支持平滑曲线和正交折线两种线路样式。
- 具备基于节点空间位置的自动路由能力。
- 支持多目标连接自适应主干与分叉，包含全部合并、部分合并、完全独立三种结果。
- 提供可靠的悬停、选中、命中测试和连接编辑体验。
- 对经典画布与 Nodes 2.0 做兼容性验证；不满足条件时安全降级。
- 不因扩展启停、保存、加载、复制粘贴、撤销重做而破坏原生工作流。

### 2.3 非目标 / 明确不做

- 不重新实现 ComfyUI 的节点执行、队列或数据流系统。
- 不自动创建、删除或移动真实 Reroute 节点。
- 连线路由能力不移动、对齐或重新排列用户节点（见第一性原理）；节点自动布局作为**独立功能**纳入范围（2026-11-07 修订，见 §4.2 / DEC-038）：仅用户主动触发、可撤销、不静默改动，且不在绘制热路径运行。
- 不改变 Link 的 source、target、slot、类型、ID 或执行关系。
- 不提供通用第三方插件市场。
- 不把手工线路布局全部转换成自动布局。
- 不承诺解决 ComfyUI 工作流本身的环路、节点兼容或执行错误。
- 不以“视觉最短线”作为唯一优化目标。

## 3. 用户与典型场景

### 3.1 目标用户

- 使用中大型 ComfyUI 工作流的创作者。
- 经常导入、复制、修改复杂工作流的用户。
- 需要向他人展示、讲解或录制工作流的用户。
- 希望减少手动整理连线时间，但不希望扩展改变工作流结构的用户。

### 3.2 核心场景

**场景 A：普通单连接**

用户把一个输出连接到另一个节点。络纹按当前线路样式寻找较自然的路径，尽量不穿过其他节点，并减少多余转弯。

**场景 B：一个输出连接多个目标**

同一输出端口连到多个目标节点。络纹先计算各条独立路径，再判断是否存在合理共享主干。结果可能是全部共享、部分共享或各走各路。

**场景 C：目标分布在不同方向**

目标节点位于源节点左右、上下或分散区域。算法不能为了公共主干让某些目标绕远，应优先保留局部自然路径。

**场景 D：节点阻挡线路**

路径中间存在其他节点。算法应尝试从节点周围经过，并平衡绕行长度、转弯和间距。

**场景 E：用户手动整理过的线路**

连接经过一个或多个原生 Reroute，或属于用户创建的手动线束。络纹必须识别手动意图，不可随意重构这部分路径。

**场景 F：节点正在拖动**

拖动过程中显示轻量、连续的预览，不应每一帧重建整棵共享树；节点释放后再完成必要的局部重算。

## 5. 线路样式与路由策略

线路样式和路由拓扑是两个不同维度，必须在代码和设置中分离。

### 5.1 平滑曲线（Bezier / Spline）

目标：保留 ComfyUI 节点图的柔和曲线观感，减少尖锐折线。

要求：

- 端口出入方向应自然，避免短线形成夸张的 S 弯或 C 形大回环。
- 线路相距较近时，曲线仍要清晰区分。
- 节点较近或位置反向时，曲率应自动收敛，不能穿越节点主体。
- 若采用正交路径作为几何骨架再进行曲线化，曲线控制点必须经过障碍物安全检查，不能因圆角/曲线平滑重新切入节点。
- 转角以贝塞尔曲线表达（2026-11-07：拐角不再使用圆弧拼接）：控制点=角点的二次表达（升阶等价三次贝塞尔），切点沿两腿各取切距，曲线全程在拐角三角形内，不因曲线化额外切入节点。
- 切距可调（0–24px，默认 10px，0 为直角）：实际取设定值与相邻两段各三分之一中的较小值，短段自动收缩，长段用满设定值。
- 共享主干与分支连接处应保持连续，不能出现不自然的尖角、断点或线路错位。

### 5.2 正交折线（Orthogonal / PCB）

目标：让线路沿水平/垂直方向行进，形成清晰、易追踪的电路板式线路。

要求：

- 使用曼哈顿路径；优先减少长度和转弯数量。
- 转角保持直角，不做常规倒角；唯一斜线表达是绕障外角大斜切（见本节书面例外）。圆角只属于 smooth 样式（§5.1），且圆角不得侵入障碍物安全边界。
- 多条线同侧离开节点时分配不同出口通道。
- 同一对节点之间存在多条连接时，应尽量采用一致走廊，并以平行线束排列，避免互相交叉。
- 不同线路占用同一走廊时应适度分道；空间不足时允许降低避障级别，但不得穿过节点主体。

**书面例外：绕障外角大斜切（用户批准，2026-11-06，替代原 4px 局部倒角）**

用户明确：几像素的微倒角与直角视觉无差别，取消；正交样式只允许**绕障外角大斜切**一种斜线表达，作为本节「禁止斜线」的唯一例外，边界如下：

- **适用范围**：仅当路径为绕开第三方节点而转折时，把该外凸转角的直角切掉一大块，用长斜边连接两腿；不作用于三通、分叉、同向分叉、公共走廊、端口出/入引脚段与普通正交阶梯。判据：转角内侧象限完整包住该节点矩形，两臂分别贴其两条垂直边，间距在绕行间隙内，且臂长越过节点角点；本连接自身的 origin/target 节点不参与判定。
- **合并树共享点一律直角**：主干 T 点、分叉点、同向分叉点、公共走廊、引脚出入段全部保持直角；同一坐标出现在 ≥2 条成员路径上即视为共享点。
- **不必 45°、不强求等边**：两条腿可用长度不同，`cutA` / `cutB` 各自独立计算；等长时自然接近 45°，一近一远时为浅角/陡角。
- **可读性与上限**：每腿切完后仍须保留 > 0 的可见正交段（实现取 `≥24px`，与默认 stub 同量级）；任一腿切完没有直段则该侧退回直角，或整体退回直角；禁止从引脚直接起飞长斜线。切角取该腿可用长度的比例，`0.6` 为固定默认；`0.35 / 0.85` 仅保留为调试对照，不改变默认行为。可用长度需扣除 stub、相邻卡片可用空间与斜边净空。
- **目的边界**：斜切服务于**视觉省位**（减少正交线在角部同时占用的两个方向空间、改善观感），**不是提供可放置节点的画布**。不放宽腿长、间隙上限或净空阈值，不承诺三角缺口能容纳常规 225px 宽卡片；单测与验收也不以「能塞进节点」为目标。
- **净空与退化**：斜边扫掠（按 `SAMPLE_STEP` 采样）穿过任何节点矩形（含 `nodePad`）或贴近其他线路（`< linePad`）时，按比例缩短切角；缩短到低于 `MIN_CUT` 仍不达标则退回直角。判据不稳定时宁可少倒或不倒。
- **与圆角互斥**：仅正交样式生效，保留可关闭开关；关闭或 smooth 样式时回到直角/圆角。
- **命中不变式**：命中、悬停、删除按**实际绘制折线**（含斜边）计算；斜切只改绘制表达，不改变图数据。
- **斜线禁令的边界**：除上述绕障外角的单段斜边外，其余段仍全部水平/竖直，不产生任意斜线走线。
- 本节其余约束（障碍安全边界、走廊一致性、不得穿过节点主体）不变。

### 5.3 原生样式

提供回到 ComfyUI 原生线路渲染的选项，并作为所有异常和不兼容情况的最终兜底。插件禁用或无法挂载路由适配器时，不得让画布失去连线显示。

### 5.4 设置建议

首版控制项应少而明确：

| 设置 | 建议默认 | 说明 |
|---|---|---|
| 启用络纹 | 开 | 总开关。 |
| 线路样式 | 正交折线或经视觉验证后的默认值 | 平滑曲线、正交折线、原生。 |
| 自动主干/分叉 | 开 | 仅针对同一输出端口的多目标连接。 |
| 节点避障 | 标准 | 影响线路绕开节点的倾向。 |
| 线路间距 | 自动 | 由线宽、线束数量和可用空间推导。 |
| 圆角半径 | 10px（可调范围 0–24px） | 可调滑块。**仅 smooth 圆角样式生效**；实际半径取设定值与相邻两段各三分之一中的较小值（短段自动收缩，长段用满设定值），0 为直角。orthogonal 下的大斜切是另一套表达（§5.2 书面例外），与圆角互斥。 |
| 调试显示 | 关 | 开发/问题诊断用途。 |

初版不要暴露大量低层算法参数。关键阈值优先由工程内部常量管理，并通过标准测试工作流校准；确认确有用户调节价值后再放进设置界面。

## 6. 自适应主干与分叉：核心差异化能力

### 6.1 输入与处理边界

对每一个源输出端口，收集它当前连接的全部有效目标连接。每条连接仍保留独立的原生 Link ID。

只有满足以下条件才进入多目标树形路由：

- 至少有两个有效目标。
- 同一源节点、同一输出 slot。
- 连接不属于已识别的手动 Reroute 路由链，或能够明确、安全地按手动锚点分段处理。
- 当前渲染器和交互适配器支持组路由与正确命中测试。

无法满足条件时，对每条连接单独路由或使用原生渲染。

### 6.2 决策原则

**共享主干是优化结果，不是强制规则。**

允许三种结果：

1. **全部合并：** 多个目标空间位置接近、方向相似，公共路径明显有利。
2. **部分合并：** 一部分目标自然共享主干，其他目标独立连接；这是必须支持的常见结果。
3. **完全独立：** 目标分散、方向相反、障碍物复杂，或共享会导致绕路时，不合并。

严禁只根据“同一个输出端口连接多个目标”就创建公共主干。

### 6.3 算法流程

建议采用“独立路径基准 + 候选共享树 + 局部优化 + 成本比较”的组合方案。

**阶段 A：计算独立基准**

- 为每个目标独立计算一条高质量路径。
- 保存每条路径的长度、转弯数、节点避障情况、交叉情况和走廊占用情况。
- 独立基准作为后续判断单条目标是否被牺牲的参照。

**阶段 B：构造候选共享树**

- 在正交路由下，以稀疏 Hanan 网格作为候选通道集合。
- 从源端口构建初始树；后续目标通过多目标 A* / 最近树边连接方式接入现有树，而不是只能接到源端口。
- 采用确定性的增量接入顺序，并至少尝试若干种有意义的目标排序，降低贪心顺序导致的局部次优。
- 连接新目标时，允许接入树上的任意可行点；接入点可以成为分叉点。
- 对候选树执行有限次数的局部优化：移动分叉点、消除多余折点、缩短共享段、检查树结构和避障。
- 候选生成必须有复杂度上限，不能在大型工作流或拖动过程中无限搜索。

**阶段 C：单目标绕行保护**

对每个目标 `i`，计算：

- `L_base(i)`：该目标独立路径长度。
- `L_tree(i)`：候选树上从源端口沿树到该目标的实际路径长度。
- `detourRatio(i) = L_tree(i) / max(L_base(i), epsilon)`。

若某目标的共享路径超过内部允许的绕行预算，应将该目标从该候选共享组中剥离，保留独立基准路径；其余目标继续评估共享树。这样实现局部拒绝，而不是整组一票否决。

初始工程阈值建议以 `detourRatio <= 1.12` 作为实验起点；该值不是已验证的普适常数，必须通过标准样本工作流测试后确定，并集中定义、可调试、可回归。若极短路径导致比例不稳定，应使用带最小分母保护的归一化代价，不能用任意大比例误判。

**阶段 D：比较是否值得共享**

共享方案至少要满足：

- 具备有意义的公共区段长度，而非为了极短重叠制造复杂分叉。
- 总体几何与视觉成本比独立路线有明确改善。
- 所有保留在共享树中的目标均通过单目标绕行保护。
- 不引入不可接受的新增交叉、节点碰撞或线路间距问题。

若收益不足，回退独立路线。若只有部分目标通过，则仅对通过的目标共享。

### 6.4 成本模型

建议使用可解释的加权成本，而不是只算线长：

`C = wL * L_unique + wB * B + wX * X + wO * O + wS * S + wD * D`

其中：

- `L_unique`：实际绘制的唯一线路长度；共享段只计一次。
- `B`：转弯数量或转弯惩罚。
- `X`：线路交叉或近距离交叉惩罚。
- `O`：节点主体碰撞的极高惩罚；节点主体原则上视为硬障碍。
- `S`：线路过近、重叠、走廊拥挤的惩罚。
- `D`：单目标额外绕行惩罚；同时受硬约束保护。

权重不应直接做成大量用户滑块。先通过固定工作流样本确定一组可解释的默认权重，并保留调试输出。

### 6.5 稳定性与滞回

当独立和共享方案的成本接近时，不应频繁切换拓扑。

- 初次计算按确定性规则得出结果。
- 已有共享拓扑只有在独立方案明显更优时才拆分。
- 已有独立拓扑只有在共享方案明显更优时才合并。
- 拓扑切换设置最小改善幅度（初始可从 5% 作为实验值开始校准）。
- 节点拖动期间优先保持上一次拓扑，释放后再判断是否需要变化。
- 路径缓存和滞回不得破坏最终结果的可复现性；工作流重新加载后必须能基于同一图状态得到确定性结果。

### 6.6 失败处理

- 树构建失败：所有目标退回独立路径。
- 某个目标绕行超预算：该目标独立，其他目标继续尝试共享。
- 路由搜索达到预算：采用已有有效缓存或原生绘制。
- 候选树出现环、断裂、端点不一致：整棵候选树作废。
- 节点移动造成缓存过期：旧路线仅可在短暂过渡中作为预览，不能作为最终命中或连接真值。

## 7. 节点避障与单条线路路由

### 7.1 正交路由基础算法

主要参考 Cable Management 的稀疏 Hanan 网格 A*：

- 使用源/目标端口、端口 stub 和膨胀后节点矩形边界构建稀疏通道。
- 状态包含当前位置和进入方向，以便计入转弯成本。
- 节点主体是硬障碍；安全间距区域可以作为软惩罚区，但不得让线路穿过节点主体。
- 线路长度、转弯、障碍距离共同参与路径成本。
- 设置最大搜索扩展数或时间预算；超限返回失败，让调用方降级。
- 对坐标、节点尺寸、端口方向做合法性检查，避免异常工作流数据击穿绘制循环。

### 7.2 端口 stub 与出入口规则

- 从端口离开后先有短直线段，避免线路紧贴节点边缘立即转弯。
- stub 长度应根据连接距离动态收缩，短距离连接不得因固定 stub 产生折返。
- 起点和终点方向必须尊重端口朝向。
- 对目标位于源节点左侧的反向连接，优先绕开节点外侧；不得用一条穿过源节点的直线作为“最短路”。
- Reroute 的端点方向应根据其上下游位置推断，使线路进入和离开方向连续。

### 7.3 多线分道与间距

- 同一节点同一侧的多条线路必须获得确定性的出口通道。
- 多条线路连接同一对节点时，尽量共享同一几何走廊并并行排列，避免交叉。
- 不同线路偶然进入同一狭窄走廊时，尝试分配平行车道。
- 若可用空间不足，不得无限增加绕行；优先保持可读性并在调试信息中标记降级。
- 线间距应考虑线宽、抗锯齿和视觉分隔，不以零间距重叠冒充合并。

### 7.4 平滑曲线的几何安全

- 曲线路径的控制点不得穿过节点主体。
- 若曲线直接生成无法可靠避障，应先生成安全骨架，再进行受约束的曲线化。
- 曲线化后的路径必须再次检测障碍物和端口出入方向。
- 曲线无法满足约束时，局部退回更紧凑的曲线或正交/原生路径；不得以外观平滑为由忽略碰撞。

## 8. 交互与命中测试

自动共享主干不能牺牲原有每条连接的可操作性。

### 8.1 基本规则

| 用户操作 | 预期行为 |
|---|---|
| 悬停共享主干 | 高亮整组逻辑连接及对应分支。 |
| 悬停独立分支 | 高亮对应的单条原生连接。 |
| 点击共享主干 | 选择该共享组中的全部原生连接。 |
| 点击独立分支 | 选择对应单条连接。 |
| 点击分叉点 | 选择共享组；不得随机命中某一条连接。 |
| 删除已选共享组 | 删除组内原生连接；行为应与 ComfyUI 原生多选删除一致。 |
| 删除单独分支 | 只删除对应 Link。 |
| 从线路拖动建立连接 | 能正确定位原始 source/target，不能把临时绘制分支误当成图连接。 |
| 断开一条组内连接 | 只移除对应逻辑连接，并重新计算剩余线路组。 |

### 8.2 命中优先级

1. 独立分支专属区段优先命中单条连接。
2. 完全共享的主干区段命中整个连接组。
3. 分叉点命中整个连接组，避免不确定选择。
4. 路线边界距离相近时采用确定性规则，不得按遍历顺序随机选中。

### 8.3 兼容性降级

如果某一版 ComfyUI 的前端选择 API 无法安全支持共享主干组选择：

- 不得留下无法选择或无法删除的线段。
- 可以退化为多股 Ribbon 呈现，每条逻辑连接仍保留独立的命中区域。
- 若连多股命中也无法保证，则关闭该版本上的自动共享，只保留单线样式和单路径路由。

### 8.4 手工路由优先级

优先级固定为：

1. 用户明确建立的原生 Reroute / 手动路径锚点。
2. 已识别的用户手动线束或第三方线路捆绑表达。
3. 络纹自动生成的主干、分叉与单条路由。
4. ComfyUI 原生默认绘制（兜底）。

MVP 采用保守策略：包含原生 Reroute 链的连接默认不参与跨目标自动合并。仍可对不违反手工锚点的独立线段进行局部样式优化；若无法确定用户意图，就保持原生路径。

对于 Zip Ties 等第三方扩展：优先检测其公开、稳定的数据标记或接口；没有稳定接口时不得依赖脆弱的 DOM 猜测。检测到冲突且无法安全协同时，关闭冲突线路的自动接管并记录诊断信息。

## 9. 数据模型与工作流安全

### 9.1 原生图数据是真实来源

ComfyUI 原生 Graph / Link 是唯一连接事实来源。络纹的路线是从图数据和节点几何派生出来的视图，不得成为第二套工作流真值。

### 9.2 禁止写入的内容

自动路由不得修改：

- Link ID。
- Link 的 origin node / origin slot。
- Link 的 target node / target slot。
- 节点 ID、节点类型、节点参数。
- 原生 Reroute 节点数量、位置和父子关系。
- 工作流执行顺序或节点连接语义。

自动分叉不得通过创建隐藏 Reroute 来实现。

### 9.3 运行时派生数据

可在内存中维护：

- 路由组 ID（由源端口和成员 Link ID 的确定性签名生成）。
- 独立基准路径。
- 共享候选树与最终树。
- 共享边段到 Link ID 集合的映射。
- 单独分支到 Link ID 的映射。
- 节点障碍快照及版本号。
- 命中测试索引。
- 路由缓存与失效状态。

这些数据不得写入工作流 JSON。用户可配置设置保存在 ComfyUI 前端设置机制中，不得偷偷改变 workflow graph。

### 9.4 连接生命周期

- 新增连接：只重算受影响源输出端口对应的连接组。
- 删除连接：移除对应成员；若剩余连接数小于 2，取消共享树，退回单线路路由。
- 修改连接目标：旧组和新组分别失效并重算。
- 节点移动/缩放/折叠：失效与该节点几何相关的局部路线。
- 节点删除：清除相关缓存和命中索引，不残留幽灵线路。
- 工作流加载/切换子图：基于当前画布实际 graph 重建缓存；不能错误读取根 graph 来绘制子图。
- 复制粘贴：不复制任何自动路由的持久化数据；新 Link 生成后重新计算。

## 10. 性能、缓存与稳定性

### 10.1 总体原则

渲染热路径只读取已经计算好的路由，不执行完整 A* 或共享树搜索。计算与绘制分离。

### 10.2 推荐架构

1. **Graph Adapter：** 从 ComfyUI 当前活动画布提取节点、端口、连接和几何信息；屏蔽不同前端版本的 API 差异。
2. **Geometry Core：** 纯函数几何模块，不直接依赖 DOM、ComfyUI app 对象或 LiteGraph 实例。
3. **Single Route Engine：** 负责单条路径、障碍物和线路分道。
4. **Branch Planner：** 负责多目标候选树、单目标绕行保护和共享决策。
5. **Route Registry / Cache：** 保存当前有效路由、组成员、拓扑版本和失效状态。
6. **Renderer Adapter：** 将共享边、分支和独立路径映射到 ComfyUI 的线路绘制、中心点、流动标记和命中测试机制。
7. **Interaction Adapter：** 负责悬停、选中、拖动、断开和多选删除。
8. **Settings：** 管理用户可见配置与默认值。

### 10.3 计算时机

- 图变化或节点位置变化时，将受影响路线标记为 dirty。
- 拖动过程中只做轻量预览；优先使用上一次路线做局部形变，必要时回到简化曲线或原生绘制。
- 节点释放后启动完整重算。
- 可在 Web Worker 中运行纯几何搜索；主线程只接收结果并校验版本号。
- 结果返回时，如果图版本或节点几何版本已经变化，则丢弃过期结果。

### 10.4 缓存键

缓存键至少考虑：

- 当前 graph / subgraph 身份。
- Link ID、source / target、slot。
- 起止端点坐标及端口方向。
- 影响该路线的局部障碍物版本或空间索引版本。
- 路由样式、避障与间距参数版本。
- 共享组成员签名与树拓扑版本。

避免每帧对全图做昂贵字符串拼接或全量几何扫描。可采用空间索引和分区版本控制。

### 10.5 防抖与滞回

- 节点拖动期间不反复进行完整多目标树优化。
- 释放后对同一帧产生的多次图事件合并处理。
- 共享/拆分使用最小改善幅度，降低拓扑抖动。
- 缓存只用于性能与过渡，不得让旧路径继续成为真实命中目标。

### 10.6 性能验收目标

性能数字必须通过固定测试工作流实测，不以宣传值代替测量。至少建立以下规模档：

- 小型：约 50 个节点 / 100 条连接。
- 中型：约 200 个节点 / 500 条连接。
- 大型：约 500 个节点 / 1,000 条连接。

验收原则：

- 渲染热路径不得运行 A*、候选树搜索或全图重规划。
- 普通鼠标移动、悬停和选择不得触发完整路由重算。
- 节点拖动期间不得因算法计算阻塞交互；预览可以短暂退化，但画布必须保持可操作。
- 中大型图首次计算允许异步完成，但在计算期间必须有安全路线显示。
- 记录路由计算耗时、搜索扩展数、缓存命中率、降级次数和主线程耗时，作为后续优化依据。

## 11. ComfyUI 前端兼容与工程实现约束

### 11.1 扩展形态

建议实现为纯前端扩展，不增加新的 ComfyUI 节点，不引入 Python 第三方依赖。若 ComfyUI 的扩展发现机制要求最小 Python 入口，只保留注册静态 `web` 目录所需的最小代码。

### 11.2 兼容范围

- 经典画布（Classic Canvas）。
- Nodes 2.0（Vue 节点界面）。
- 子图 / Subgraph（必须用当前画布绑定的 graph，而不是假定 `app.graph` 永远是活动图）。
- 节点折叠、组拖动、多选、节点缩放和连接预览。

首发版本要在明确列出的 ComfyUI 与前端版本矩阵中测试。没有实测通过的版本不得标记为完全支持。

### 11.3 API 使用策略

- 优先使用 ComfyUI 已公开的扩展注册、设置、事件和绘制接口。
- 若实现确需包装内部绘制方法或 LiteGraph 原型，所有包装必须封装在版本适配器中，并具备能力检测、幂等安装、原函数保留和卸载/回滚能力。
- 不允许在无法识别的方法上静默写入或反复包装。
- 不依赖 Vue 私有实例、组件内部状态或固定 DOM 层级来推断图数据。
- 路由渲染异常必须在单条线路级捕获；任何异常不得逃逸并破坏整个 ComfyUI 绘制循环。
- 对绘制 API 的每次适配都必须有兼容性测试或手工测试记录。

### 11.4 与其他扩展冲突

重点测试：

- ComfyUI 原生不同 Link Render Mode。
- ComfyUI Cable Management。
- ComfyUI NKD Reroutes。
- ComfyUI Zip Ties。
- 其他会包装 `drawLinkPath`、`renderLink`、`drawConnections`、命中测试或连接预览的扩展。

不能保证与所有扩展同时启用。冲突时应明确提示并安全关闭冲突能力，不得让画布失效或修改原生连接。

## 12. 设置界面与用户体验

### 12.1 设置入口

放入 ComfyUI 原生设置体系或独立轻量侧边栏面板，避免占用主画布空间。

### 12.2 首版界面

建议仅提供：

- Enable LuoWen：总开关。
- Wire Style：Native / Smooth / Orthogonal。
- Adaptive Branching：自动主干与分叉开关。
- Node Avoidance：Low / Standard / High（或少量离散档位）。
- Show Debug Routes：调试路径显示开关。
- Reset to Defaults：恢复默认值。

线宽、分叉阈值、最大搜索扩展数等先由内部配置管理，不把工程参数堆给普通用户。

### 12.3 默认体验

- 安装后不需要用户逐条调整线路。
- 默认开启安全、可预测的自动路由能力。
- 用户切换线路样式后，现有工作流立即更新视觉效果，不改变连接数据。
- 自动共享只在成本收益明确时出现；用户不需要理解 Steiner Tree、A* 等算法术语。
- 调试模式仅用于开发诊断，不成为普通用户必须理解的功能。

## 13. 竞品与成熟项目调研

调研的目的不是照搬某个扩展，而是识别已被验证的子问题、复用边界和我们真正需要自研的差异化能力。

### 13.1 Cable Management for ComfyUI

- 仓库：<https://github.com/vtokic/comfyui-cable-management>
- 许可证：MIT。
- 已公开能力：Daisy-chaining、PCB 正交路由、Ribbon cables、反向连接处理、节点避障、走廊分道。
- 值得研究的实现：`web/pathing/router.js`、`web/pathing/registry.js`、`web/pathing/combs.js`、`web/pathing/trace.js`，以及 `SCHEMA.md` 中对工作流持久化边界的设计。

| AT-013 | 悬停共享主干 | 共享主干段高亮整组连接；悬停分支段只高亮该分支，主干保持常态。 |

| AT-015 | 共享主干段右键 | 出现「删除这一组（N 条）」并保留单条删除；分支段只有单条删除。 |
| AT-016 | 点击独立分支 | 选择单条原生连接。 |
| AT-017 | 删除共享组 / 单分支 | 整组删除一次事务、只产生一条 undo；单分支删除沿用原生单条语义。 |
| AT-018 | 用户手动 Reroute | 不被自动主干覆盖或移动。 |
| AT-019 | 节点拖动 | 预览连续、画布可操作；释放后正确重算。 |

| AT-028 | 非法或缺失几何信息 | 忽略异常数据并安全降级，不崩溃。 |

> **AT-013/015/017 口径修订（DEC-021，2026-11-07）**
>
> 旧口径要求「点击共享主干选择共享组全部原生连接」，宿主前端不支持：可选中类型枚举只有 `node / group / reroute / io`，不含 link（`selectionState.ts:7`）；`selectedItems` 是 `Set<Positionable>`，link 无法容纳（`LGraphCanvas.ts:746`）；`deleteSelected()` 只处理 node / group / reroute（`LGraphCanvas.ts:4787-4821`）；且无批量链路删除接口（`LGraphCanvas.ts:6760-6775`）。
>
> 新口径为「组高亮 + 组删除」：悬停共享主干段高亮整组、悬停分支段只高亮该分支；共享主干段右键提供「删除这一组（N 条）」（一次事务、一条 undo），分支段保留原生单条删除。键盘 Delete 与原生单条删除语义不变；不改动任何 Link ID、origin/target slot 与节点数据。

### 14.2 算法固定样本

必须建立可重复的 fixture 测试集，至少包含：

1. 同一水平线上的 2、3、5 个目标。
2. 目标垂直堆叠。
3. 目标集中在一侧、另一侧有远端目标。
4. 目标位于上下左右不同方向。
5. 目标被一个或多个节点阻挡。
6. 狭窄通道与密集节点。
7. 源或目标附近存在 Reroute。
8. 多条线路在局部走廊交叉。
9. 节点间距很短、端口高度不一致。
10. 节点折叠、尺寸变化和分组移动。

每个 fixture 应记录输入图、预期路由拓扑类别（合并/部分合并/独立）、主要约束和可接受代价范围。优先断言结构属性和约束，不要只对 SVG 或像素截图做脆弱快照测试。

### 14.4 数据不变性测试

每次关键操作前后，比较原生 graph 数据：

- 节点数量、节点 ID、节点类型与节点位置（用户操作本身造成的变化除外）。
- Link 数量、Link ID、源节点/slot、目标节点/slot、Link 类型。

- 初次建图时间。

- 多目标树计算耗时。

性能验收以真实数据和测试机器信息为准。任何算法不得同步阻塞每帧渲染。

## 18. 最终产品原则（实现不可偏离）

1. **不改工作流，只改善表达。** 自动主干和分叉是视觉路由，不是新建的真实数据节点。
2. **先独立，后共享。** 独立路径是每个目标的质量基线；共享必须证明自己值得。
3. **允许部分共享。** 不把多目标连接视为一个不可拆分的整体。
4. **单目标不背锅。** 不能为了全局线长牺牲某一条连接的合理性。
5. **手动意图优先。** 用户明确建立的路径锚点和线束高于自动整理。
6. **交互与视觉同等重要。** 任何可见线路都必须有正确、可预测的命中和编辑语义。
7. **性能预算前置。** 路由不在绘制热路径中运行；大型图必须有上限和降级。
8. **失败可退回原生。** 算法和 API 不确定时，宁可不优化，也不能破坏画布或连接。
9. **可验证而非凭感觉。** 每个优化都要有固定 fixture、结构断言和真实前端测试。
10. **成熟项目借鉴有边界。** 研究成熟实现，合规复用可用代码；多目标自适应主干仍由络纹自主实现。
