# routing · 路由几何经验

## R1 · 单主干 + 分叉后公共走廊，已天然实现「顺序抽头」

- **主张**：同源多目标只需保证「分叉前共用一条线、分叉后同向共线合并」，不必再实现逐段抽头（Daisy-Taps）。
- **适用**：宿主按 `link.path` 绘制折线的正交/平滑骨架；同源多目标且允许部分或全部合并。
- **Why**：抽头与「单主干 + 分叉后公共走廊」的绘制并集完全相同；宿主 A/B 实测开/关抽头逐像素 0 差异。
- **How**：按输出端口分组 → 取合法最晚分叉点 → 分叉后对同向共线且连续的分支合并为一个走廊段 → 进入引脚前分离。验证方式：抽头开/关两次截图做像素 diff。
- **反例**：在「完全独立」组上套抽头，只增加几何复杂度，画面无收益。
- **事实源**：DEC-019 撤除结论；阶段 3C 实现已撤回；宿主 A/B 实测。

## R2 · 输入侧走廊按「首个接近方向」嵌套分道

- **主张**：同一目标节点多个输入引脚的竖直走廊，必须按线的首个接近方向分组排序，不能按 `target_slot` 升序摊开。
- **适用**：正交路由；同一目标节点 ≥2 个输入引脚，来源分布在目标节点上方与下方。
- **Why**：按 slot 摊开会造成跨组交叉；按接近方向分组后，组内单序、组间一次编号即可保证目标侧不交叉。
- **How**：上方来的引脚越高越贴近节点；下方来的镜像（引脚越高越远离节点）；水平接近的线放最外层；跨组连续编号一次排布。
- **反例**：按 slot 升序会把「来自上方的低引脚线」排到高引脚线外侧，形成同组交叉。
- **事实源**：阶段 2 提交 `8614a8a`；`luowen/web/routing/laneAssign.js`；`docs/routing-algorithm.md`。

## R3 · 正交样式只允许一种斜线：绕障外角大斜切

- **主张**：正交风格的唯一斜线表达，是「为绕开第三方节点而形成的外凸直角整块切掉」；三通、分叉、共享点、公共走廊、引脚出入段与普通阶梯一律保持直角。
- **适用**：正交样式；存在第三方节点迫使线路绕行并形成外凸转角；用户已否决 4px 微倒角与普通阶梯倒角。
- **Why**：斜线一旦泛化会破坏正交网格的可读性；只切「绕障产生的外凸角」既省位又不产生语义歧义。
- **How**：先判定该直角是否由绕障产生 → 用长斜边连接两腿 → 默认斜切比例 0.6 → 与 smooth 圆角互斥。
- **反例**：把普通阶梯切成 45°、或给所有转角加微倒角，会让线团重新模糊并违背用户预期。
- **事实源**：阶段 2 提交 `8614a8a`；`luowen/web/geometry/chamfer.js`；GLOSSARY「绕障外角大斜切」。
